# NewsVerify 修复与升级说明（2026-11-17）

> 后续更新：v0.5.0 增加多风格界面、统一版本与三语文档；v0.5.1 修复首次部署后发现的运行时 JS 语法错误；v0.5.2 增加严格可信来源白名单，移除百度等聚合站。详见 `CHANGELOG.md` 与 `docs/SOFTWARE.zh-CN.md`。

## 一、本次修复了什么

### 1. 前端任务列表全空、按钮点不动（根因）
`app/web/app.py` 的 `renderEvents()` 模板字符串在第 774 行**提前闭合**（`</div>\`` 后还有裸 HTML），导致整段 `<script>` 解析失败——所有 `onclick` 函数未定义、列表不渲染。这就是"后台有数据、前台全空、点击无反应"的直接原因。

同时给列表渲染加了**逐条 try/catch + 字段防御**（`e.claims` 等可能为 null），单条脏数据不会再让整个列表白屏。

### 2. 外部 API 全部换成你提供的新接口
- 主：`http://192.168.8.253:3065/v1`
- 备：`https://api.caishen.today:8443/v1`
- Key：已写入 `.env`，此处不公开密钥

并且：
- 旧模型 `auto/deepseek-v4-flash` 在新 API 上**不存在（404）**，改为实测可用的 `gemini-3-flash`。
- `LLMClient` 增加**主备自动切换 + 端点级熔断**：主 API 连续失败后自动切备用，无需人工干预。
- 关闭 openai 客户端内部重试（避免 60s×N 超时叠加）。

### 3. 新增系统运行状况面板（页面下方，支持刷新）
- 后端新增 `GET /api/system`：真实采集 CPU / 内存 / 磁盘 / 进程 RSS / 运行时长，并**实时探测**每个外部 API（主、备、搜索）的在线状态与响应延迟。
- 前端每 30 秒自动刷新，也可点"🔄 刷新"手动刷新。
- 只用了标准库，没有引入 psutil 等新依赖，容器构建不受影响。

### 4. 任务提交后立即显示 + 状态 + 完整节点内容
- 提交后**立即**在任务列表顶部插入该任务（optimistic UI），并弹出详情窗口。
- 详情窗口在任务 running/queued 时**每 3 秒自动刷新**，实时展示进度。
- 完整展示：6 大方法节点状态（主张拆分/证据检索/独立性判定/LLM判定/六体系元数据/持续追踪）+ 处理进度时间线 + 断言/判定标签/置信度/证据/反证/缺口/Top10 媒体。

### 5. 两个健壮性修复（防止再次卡死）
- **Bot 降级**：Telegram token 缺失/失效不再让 Bot 和 Worker 整个崩溃，核查照常进行，只跳过推送。
- **僵尸任务回收**：Worker 启动时会把超过 10 分钟仍卡在 running 的任务重置回 queued 重新处理。

## 二、部署到 NAS（群晖）

> 代码已同步一份到 `/Volumes/OS2App/AiColding/NewsVerify`（你给的物理地址）。NAS 上实际运行目录按部署文档是 `/volume2/docker/newsverify`。

1. 把更新后的代码同步到 NAS 运行目录（在 Mac 上执行）：
   ```bash
   rsync -av --exclude='.venv-verify' --exclude='__pycache__' \
     /Volumes/OS2App/AiColding/NewsVerify/ \
     <你的NAS用户>@192.168.8.253:/volume2/docker/newsverify/
   ```
2. 在 NAS 上重建并启动：
   ```bash
   cd /volume2/docker/newsverify
   sudo docker compose up -d --build
   ```
3. 清理历史失败任务（16 个因旧 API 模型不存在而 failed 的垃圾任务）：
   ```bash
   sudo docker compose exec bot python scripts/clean_failed_jobs.py        # 先看预览
   sudo docker compose exec bot python scripts/clean_failed_jobs.py --apply  # 确认后清理
   ```
4. 验证：
   - `curl http://127.0.0.1:8095/health` → `{"status":"ok"}`
   - 浏览器打开首页，登录后查看下方"系统运行状况"面板，确认主/备 API 在线。

## 三、配置说明（.env）

```
LLM_BASE_URL=http://192.168.8.253:3065/v1          # 主
LLM_BASE_URL_FALLBACK=https://api.caishen.today:8443/v1  # 备
LLM_API_KEY=<redacted>
LLM_MODEL=gemini-3-flash
LLM_JUDGE_MODEL=gemini-3-flash
POSTGRES_USER=newsverify / POSTGRES_PASSWORD=newsverify / POSTGRES_DB=newsverify
```

> 注意：群晖上环境变量由 docker compose 的 `env_file: .env` 注入，请确认 NAS 上的 `.env` 也已更新为上述内容（尤其是 `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`），否则仍会用旧的失效配置。
